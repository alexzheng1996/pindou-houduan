# 新项目 SOP

> 本 SOP 适用于拼豆后端 Workspace 的所有正式项目。执行任何正式项目时，必须先创建 `projects/project-三位编号-项目名称/`，并把该项目的全部长期资料留在该目录内。

## 1. 是否需要立项

满足任一条件就必须创建正式项目文件夹：

- 有明确业务或工程目标，且需要持续执行；
- 有独立交付物，例如后端能力、接口、脚本、调研报告、数据包、测试结果或 SOP；
- 预计会产生多份需求、资料、数据、截图、代码、日志或输出；
- 后续需要验收、复盘、迁移、交接或独立 Git 提交。

以下不直接占用项目编号：临时讨论、单次问答、一次性命令查询、无明确交付物的想法、只作为输入的外部参考文件。先归类，目标和验收标准明确后再立项。

## 2. 创建前检查

1. 阅读 `docs/workspace/全局工作台.md` 和本 SOP。
2. 执行 `git status --short --branch`，确认当前分支和未提交内容可承载本项目。
3. 检查已有项目编号，选择下一个未使用的三位编号：

   ```bash
   find projects -maxdepth 1 -type d -name 'project-[0-9][0-9][0-9]-*' | sort
   ```

4. 明确项目名称、目标、范围、不做事项、交付物、验收标准，以及是否涉及 PixoMosaic 联调。
5. 创建项目文件夹和 README 后，才开始保存项目资料、代码或输出。

## 3. 命名规范

- 固定格式：`project-三位编号-项目名称`。
- 示例：`project-001-拼豆后端`、`project-002-图纸异步生成接口`。
- 编号从 `001` 连续递增，不跳号、不复用。
- 项目名称应简短、具体，使用中文、英文或拼音均可；避免空格、特殊符号和 `temp`、`test`、`new-project` 等模糊名字。
- 文件命名应表达内容和用途；日期记录使用 `YYYY-MM-DD-主题.md`，接口文档建议使用清晰的中文标题或稳定英文名。

## 4. 标准目录与用途

```text
projects/project-001-拼豆后端/
├── README.md
├── docs/
├── src/
├── tests/
├── scripts/
├── data/
│   ├── raw/
│   └── processed/
├── output/
├── logs/
└── handoff/
```

| 位置 | 必须存放的内容 |
| --- | --- |
| `README.md` | 目标、范围、不做事项、当前状态、运行方式、验收标准、关键结论 |
| `docs/` | 需求、技术方案、接口契约、决策记录、复盘、联调说明 |
| `src/` | 此项目的后端源代码和项目内配置 |
| `tests/` | 单元、集成、接口与联调测试 |
| `scripts/` | 仅服务本项目的自动化、迁移、验证脚本 |
| `data/raw/` | 可追溯原始输入；不放敏感凭据 |
| `data/processed/` | 清洗后的中间数据、可复现实验数据 |
| `output/` | 报告、导出物、交付包和最终产物 |
| `logs/` | 运行、验证和排障日志；不得写敏感信息 |
| `handoff/` | 交接说明、下一步、验收证据和给其他 Codex 的提示词 |

## 5. 强制存放边界

- 项目有关的所有长期内容必须在该项目目录下：需求、资料、截图、数据、代码、配置、脚本、日志、测试、输出和交付物均不可例外。
- 不得将项目文件长期放在 Workspace 根目录、桌面、下载目录、系统临时目录或 Workspace 外部路径。
- 如果浏览器、CLI 或第三方工具默认把文件输出到其他位置，必须在当次任务结束前迁入项目目录并在 README 或日志说明来源。
- 真正无保留价值的临时文件可以删除；有复盘价值但不属于正式项目的资料，不创建项目号，待项目明确后再迁入对应目录。
- 凭据、密钥和账号不应存入项目目录；使用环境变量或受保护凭据文件，并只在文档中说明变量名和权限前置条件。

## 6. PixoMosaic 前后端协作检查

涉及 `/Users/alexwork/Documents/PixoMosaic` 时，额外完成以下动作：

1. 在当前后端项目 `docs/` 创建或更新接口契约。
2. 明确接口版本、鉴权方式（仅写机制、不写密钥）、请求字段、响应字段、错误码、异步状态和兼容性策略。
3. 用示例请求/响应和自动化测试验证后端，不以直接读前端内部文件替代接口验证。
4. 记录联调环境、前端对应版本或提交标识、验证结果和已知限制。
5. 不修改 PixoMosaic 文件，除非用户另行明确授权；两个仓库分别管理各自 Git 改动。
