### 已执行的 M0-B 最小安装顺序（其他电脑复现）

1. 安装 `fnm`，安装 Node 24，并将版本写入项目版本文件和 `package.json` 的 `engines`。
2. 确认 pnpm 版本，启动 Docker Desktop，验证 Docker 服务而不只是命令存在。
3. 在当前项目 `src/service/` 内建立官方 Payload 最小骨架并锁定官方包版本；不安装电商模板、OAuth/RBAC 第三方核心插件或无关商城组件。
4. 用 Docker 启动本地 PostgreSQL，建立不含真实数据的开发数据库；迁移只能由显式 `pnpm migrate` 执行，不开启 Payload 自动 schema push。
5. 创建 `.env.example`，只列变量名、用途和非敏感示例；真实 `.env` 保持忽略。
6. 运行健康检查、数据库迁移、最小自动化测试、生产依赖审计和 Docker 构建；证据见 `docs/验收/阶段验收记录.md`。

## 2. 暂时不需要安装或购买的东西

- 不下载“独立 Payload 后端安装包”：Payload 是写入本项目 `package.json` 的 Node 依赖，不是独立桌面应用。
- 不购买 VPS、自建服务器、Redis、消息队列、搜索引擎、支付服务或邮件付费套餐。
- 不安装 Shopify、Stripe、物流、库存、商城、评论、私信、自动审核相关组件。
- 不全局安装 Payload，不向 PixoMosaic 前端仓库写入依赖，也不把用户文件放到应用服务器本地磁盘。

## 3. M1 部署前需要业务方创建或确认的账号/权限

以下项目只在本地 M1 最小功能、部署检查和费用 Go 全部通过后才需要真正开通。所有账号应由业务方持有主账号；开发协作者按最小权限加入，密钥只写入受保护的环境变量。

| 能力 | 推荐的首选/备选 | 业务方要确认或提供 | 不应交给项目仓库的内容 |
| --- | --- | --- | --- |
| 托管 PostgreSQL | 首选比较 Neon；备选 Supabase、Railway/Render 托管库 | 测试与生产是否分开、区域、预算上限、备份恢复责任、可创建项目的管理员 | 数据库密码、连接串 |
| 对象存储 | 首选比较 Cloudflare R2；备选 AWS S3 | 测试/生产桶名称、地域、生命周期、谁可创建最小权限访问密钥 | Access Key、Secret Key、文件 URL 签名 |
| 事务邮件 | 首选比较 Resend；备选 Postmark | 发件域、DNS 验证权限、测试收件邮箱、日发送量预算 | API Key、真实收件人名单 |
| Google 登录 | Google Cloud OAuth | 可用项目、同意屏幕、测试用户、回调域名 | Client Secret |
| 应用托管 | 首选比较 Railway；备选 Render、Fly.io | 区域、预算、谁有部署/日志/回滚权限、镜像或 Git 连接授权 | 平台 Token、部署密钥 |
| 域名与 DNS | Cloudflare（业务方自行管理） | 主域名已确认 `pixomosaic.com`；仅在 Railway 实际域名分配后自行添加 `api-test.pixomosaic.com` CNAME | 域名平台登录凭据、Cloudflare 密码或 API Token |
| 合规文本 | 业务方或法务 | Privacy Policy、Terms、退款/取消、投诉入口的正式链接与版本 | 客户资料、未公开法务文件 |

## 4. 团队验证环境的最小形态

```text
PixoMosaic 测试前端
        │ HTTPS / 受控 CORS
        ▼
api-test.<主域名>（Payload + Docker 部署）
        ├── 独立测试 PostgreSQL
        ├── 独立测试 R2/S3 桶
        └── 测试标识的事务邮件
```

- 只允许邀请/白名单测试邮箱注册，不公开开放注册。
- 测试、生产必须使用不同的数据库、存储桶、邮件配置和密钥；测试数据可以整体销毁。
- 初期应用容量按 2 vCPU / 4 GiB 内存估算；应用磁盘只放短暂运行文件，数据库和用户文件均不放在那里。
- 部署采用 Git → Docker 镜像 → 测试环境 → 验收 → 生产环境的路径，不通过手工压缩 ZIP 上传发布。
