# M0 复用优先评估

> 评估日期：2026-08-18
> 状态：M0 复用评估与项目内安装已完成；实际锁定版本、许可证和生产依赖审计已经在本地验证。后续升级依赖时仍须重新执行同类检查。

## 结论

推荐复用 Payload 官方基础能力并进行业务改造，不复制一个完整的电商模板。Google 登录的第三方认证方案另行核查，只有通过 PoC 才可引入。

复用范围：官方 Payload 空白项目结构、`payload`、`@payloadcms/next`、`@payloadcms/db-postgres`、`@payloadcms/storage-s3`、`@payloadcms/email-resend`，以及 PixoMosaic 现有代码中的数据语义作为契约输入。

自建范围：PixoMosaic 的作品数据模型、访问控制、50 个作品限制、删除回收、反滥用、社区治理、材料清单、订单状态机和审计规则。

## 候选比较

| 候选 | 适配度 | 复用部分 | 不引入部分 | 主要风险 |
| --- | --- | --- | --- | --- |
| Payload 官方仓库与 blank 模板 | 高 | 项目结构、Admin/API 基础、配置方式、测试脚本 | 不复制模板站点、电商页面或示例业务 | 模板代码可能和当前稳定包不一致；用创建器生成最小结构并锁定实际包版本 |
| Payload 官方 PostgreSQL 适配器 | 高 | 数据库连接和迁移基础 | 不把业务表直接照搬为最终模型 | 迁移必须进入发布流程并可回滚 |
| Payload 官方 S3 存储适配器 | 高 | S3/R2 文件适配、客户端上传指令、签名下载能力 | 不把原图设为公开资源，不依赖服务器本地磁盘 | 桶权限、CORS、短期签名和孤儿文件清理需自定义验证 |
| Payload 官方 Resend 邮件适配器 | 高 | 事务邮件发送适配 | 不把邮件发送当作状态唯一事实 | 退信、重试、测试/生产发件域隔离需记录 |
| PixoMosaic 现有 IndexedDB/画板类型 | 高（仅作为输入） | `SavedPatternAsset`、`BoardState`、`MappedPixel`、草稿版本和导出选项的业务语义 | 不复制 IndexedDB/localStorage 实现，不把 data URL 当后端文件 | 前端类型会变化；必须冻结 `WorkDocument.schemaVersion` |
| 第三方 Payload OAuth/RBAC 插件 | 分方案评估 | `payload-auth + better-auth` 可作为 Google 登录候选，需通过本地 PoC | 不引入 `payload-authjs`，不把任何插件直接视为完整 RBAC | 可能替换 Local Auth、重建 Users 并新增认证集合；必须验证迁移、会话桥接和账号绑定 |
| 官方电商模板 | 低 | 不直接复用 | 不引入购物车、商品、Stripe 和模板页面 | 与 PRD 第一版人工订单边界冲突，导致范围膨胀 |

## 评估证据

- 2026-08-18 的只读 npm 核验：`payload`、`@payloadcms/db-postgres`、`@payloadcms/storage-s3`、`@payloadcms/email-resend` 均为 `3.88.0`、MIT；`payload` 声明 Node `^18.20.2 || >=20.9.0`。
- 2026-08-18 的 GitHub 只读核验：`payloadcms/payload` 为 MIT，主分支当日仍有推送。活跃度不代表业务安全；M0-B 已对锁定版本执行生产依赖审计，后续升级仍须重新检查。
- 官方仓库包含 PostgreSQL、S3/R2、Resend 等官方包，适配点比第三方插件更容易追踪。
- 官方 S3 适配器明确支持客户端上传指令和签名下载，且启用后会关闭本地文件存储；这正好对应私有原图与订单文件不落应用磁盘的边界。
- `@payloadcms/plugin-s3-storage` 不是可用的官方包名；不得按该名称安装。当前官方适配器为 `@payloadcms/storage-s3`，不再依赖 Payload 2 的云存储插件路径。
- PixoMosaic 当前 `SavedPatternAsset` 和 `BoardState` 已包含作品所需的大部分业务语义，但图片目前使用 data URL/IndexedDB 存储，不能直接作为云端协议。
- 官方 `template-website`/`template-ecommerce` 仓库更新较旧或业务范围不匹配，因此只参考结构，不整包下载。

## 实施边界

1. 已使用官方 blank/创建器建立最小 Payload 服务并切换 PostgreSQL 适配器；不复制官方电商模板。
2. 已锁定版本、license、包管理器和构建脚本；所有依赖写入后端项目 `package.json` 与 lockfile，并执行生产依赖审计。
3. M1 的邮箱密码基础先使用 Payload 官方 Local Auth 能力；Google OAuth 已完成只读核查，候选为 `payload-auth@3.0.0 + better-auth@1.7.1`，不在 PoC 通过前安装第三方插件。
4. M1 的文件使用官方 S3 适配器连接 R2/S3；原图、图纸 JSON、导出物采用私有桶和短期授权下载。
5. 任何下载的模板、示例和第三方代码必须保留来源、许可证、版本与明确不引入部分；不复制无关目录和隐含账号依赖。

## M0 复用验收

- M0-B 已从官方基础结构生成独立 Payload 项目，并在项目内锁定版本。
- PostgreSQL、S3/R2、邮件适配器均能在不泄露密钥的前提下完成本地/测试配置说明。
- M1 不依赖未经审查的第三方 OAuth/RBAC 插件。
- PixoMosaic 前端数据只作为 `WorkDocument` 契约输入，不产生跨仓库源代码复制。
