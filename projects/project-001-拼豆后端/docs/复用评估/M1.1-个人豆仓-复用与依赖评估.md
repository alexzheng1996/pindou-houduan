# M1.1 个人豆仓：复用与依赖评估

> 状态：已完成复用决策并落地 CSV 解析依赖。已核对本地前端资产和截至 2026-08-22 的包元数据；未连接任何云服务。

## 结论

推荐“**复用现有前端统计与规格资产 + 后端小型账本自建 + CSV 优先**”。现有 PixoMosaic 已有颜色统计、2.6/5mm 规格和颜色列表 UI，能覆盖展示侧的大部分需求；但它没有登录、服务器 API、事务库存或跨设备隔离，不能直接复用为库存系统。

CSV 的解析在导入阶段采用成熟且 MIT 许可的 `csv-parse`；当前不引入 Excel。`exceljs` 虽为 MIT，但增加 Excel 解析攻击面和维护成本，在 CSV 业务闭环验证前不值得引入。

## 候选对比

| 候选 | 适配度 | 优势 | 局限/不采用原因 | 可复用或采用部分 | 风险 |
| --- | ---: | --- | --- | --- | --- |
| PixoMosaic 现有色号、规格、颜色统计与右侧 UI | 高 | 已有 291 个 HEX、5 套显示系统、`BeadSizeMm`、单图/画板最终用量统计 | 无认证、事务、库存历史、导入预检或跨设备隔离；当前“漫漫 S4”有映射歧义 | 显示色号、规格选择、颜色行和浏览器文件选择交互 | 不可把前端“首项匹配”映射当作导入真值 |
| Payload 默认 Collection REST / Admin | 低 | 已在后端存在数据模型能力 | 不能表达用户业务 API、完成制作原子扣减、软删回滚或最小响应投影；后台暴露面不符合私有库存 | 只用 Payload 的集合、事务和迁移基础 | 不直接向前端开放 REST/GraphQL |
| `csv-parse@7.0.2`（Adaltas node-csv） | 高 | MIT；流行的 Node CSV 解析器；可严格控制列、行数和 UTF-8 输入 | 需新增受控依赖和版本锁定；不能解决色号映射本身 | M1.1 CSV 预检服务端解析 | 导入时须限制文件大小/行数，不把解析异常回传内部堆栈 |
| `exceljs@4.4.0` | 中 | MIT；可处理 XLSX 读写 | 当前前端无 XLSX 需求或依赖；复杂表格、公式和大文件增加维护面 | CSV 验收后如仍有真实 Excel 需求再单独评估 | 不在第一版安装；需要文件大小、工作表、公式和压缩炸弹防护 |
| `xlsx@0.18.5`（SheetJS CE） | 中 | Apache-2.0；生态广 | 与 ExcelJS 功能重复，当前没有比 CSV 更直接的业务价值 | 不引入 | 版本停留较旧；不为“可能需要 Excel”预装 |

## 已核对的本地复用资产

- `PixoMosaic/src/utils/beadSize.ts`：唯一的 `2.6 | 5` 规格类型和尺寸换算。
- `PixoMosaic/src/utils/colorSystemUtils.ts` 与 `src/app/colorSystemMapping.json`：5 套显示色号与 291 个底层 HEX；只适合显示/受控数据源，不可直接作为服务端导入校验函数。
- `PixoMosaic/src/app/page.tsx`：单图的 `colorCounts` 与现有右侧颜色列表，可插入只读库存状态。
- `PixoMosaic/src/app/board/page.tsx`、`src/components/BoardColorStats.tsx`：已经按画板最终可见格统计颜色，不能改为图层简单求和。
- `PixoMosaic/src/utils/localAssetLibrary.ts`、`src/utils/boardDraftStorage.ts`：仅本机 IndexedDB/草稿，不可复用为登录用户库存或云作品存储。

## 明确不引入

- 不引入 ERP、WMS、Shopify/订单库存、Redis、消息队列或额外 BaaS；它们不能减少个人豆仓最关键的账本与事务复杂度，反而增加费用和运维。
- 不复制前端源代码或将其 IndexedDB 数据结构同步到后端。
- 不引入未经确认的美国品牌色表、爬虫或网络色卡。
- 不在 CSV 验收前安装 Excel 依赖。

## 最小落地边界

1. 后端先实现余额、操作头/明细、事务 API、图纸服务端扣减和自动化测试。
2. 前端复用现有颜色统计与规格选择，只读显示库存后再做 `/inventory`。
3. CSV 导入使用服务端预检和确认提交；美国色号映射在业务方确认品牌、版本和数据来源后启用。

- 后端使用项目内版本化前端色表快照，快照 SHA-256 为 `32dad53ae0a650730df91480f5304691ce0c4661c4f49056f1d7261a22e5456d`；仍由服务端对 `0/1/多` 映射做预检，漫漫 `S4` 被拒绝，不采用前端首项匹配。
