# Spec：M1 审计与反滥用

> 状态：本地实现并验证完成。仅覆盖 M1 已认证业务 API 与本地认证闭环；不接入 Redis、WAF、设备指纹、IP 原文、第三方日志平台或云资源。team-test/生产必须在部署前重新确认阈值、保留期和边缘层策略。

## 1. 目标与范围

目标是防止已登录用户通过高频保存、上传或下载造成无控制的数据库、解码和本机磁盘消耗，并为账户、私密作品与文件的关键状态变化保存最小、可关联的安全证据。

本阶段保留 Better Auth 的数据库认证限流：注册 `5/60 秒`、密码登录 `10/60 秒`、重设申请 `5/60 秒`，以及单账号连续 5 次密码失败锁定 15 分钟。业务 API 不复用 Better Auth 的 `rateLimit` 表，而按已验证用户和业务动作单独计数。

## 2. 最小业务限流

| 操作类别 | 本地初始规则 | 目的 |
| --- | --- | --- |
| 作品创建、保存、取消草稿、删除申请 | 每用户 120 次 / 10 分钟 | 允许首次导入至多 50 个作品，限制自动保存失控。 |
| 上传 intent | 每用户 12 次 / 10 分钟 | 覆盖每作品最多 10 张图和少量重试。 |
| 二进制 PUT | 每用户 15 次 / 10 分钟 | 在读取文件字节前限制大文件解码与磁盘写入。 |
| 上传 confirm | 每用户 12 次 / 10 分钟 | 限制重复哈希/图片校验负载。 |
| 私有文件下载 | 每用户 20 次 / 10 分钟 | 限制大文件连续拉取。 |

- 桶的唯一键为 `actor_id + scope + window_started_at`，使用 PostgreSQL 原子 `INSERT ... ON CONFLICT ... DO UPDATE ... WHERE` 计数；不能先查询后更新。
- 达到上限返回 `429 RATE_LIMITED` 与 `Retry-After`，不返回用户、作品是否存在、额度余量或限流内部状态。
- 限流在活动会话和可信来源校验后、解析 JSON/读取二进制前执行。它按请求尝试计数；幂等保证不重复改变状态，但不替代请求成本控制。
- 此规则不收集 IP、User-Agent、设备指纹或请求体。上线后的 IP/慢请求/WAF 限制属于可信反向代理边界，不能在当前 Next 路由中相信客户端可伪造的转发头。

## 3. 最小审计模型与隐私边界

审计表为内部 PostgreSQL 表 `security_audit_events`，没有 Payload REST 或业务 API 读入口。记录字段仅为：内部 actor ID（可为空）、受控动作枚举、`allowed|denied`、固定路由、资源类型、资源公开 ID、`requestId`、固定原因码和时间。

必须记录：注册、邮箱验证、已知账号登录成功/失败/锁定、重设申请/完成；作品创建、保存、取消草稿、删除申请；上传 intent、成功上传、确认、私有下载；以及业务限流拒绝。成功的业务写入和审计写入在同一数据库事务内；下载先记审计再返回字节。

审计绝不记录：邮箱、密码、OTP、Cookie、Token、IP、User-Agent、Origin、完整 URL、请求/响应体、作品标题/格点、文件名、文件字节、SHA-256、对象键或本机路径。

- 认证审计和业务审计都附带 `X-Request-Id`，便于最小范围关联；认证响应保持 Better Auth 原有 JSON 格式，避免无必要契约破坏。
- 审计保留 90 天；业务限流桶保留 2 天；24 小时过期的幂等缓存由同一受控清理入口清除。保留期与团队/生产环境的法律和业务要求不一致时，必须先确认后调整。
- `pnpm cleanup:security` 仅删除上述过期记录，不触碰用户、认证会话、作品、历史快照或对象文件。
