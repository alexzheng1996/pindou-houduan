# Spec：M0 基础架构、环境与 M1 接口冻结

> 状态：**M0 技术验收已于 2026-08-19 完成；M0 的业务 Go / No-Go 等待团队验证环境的供应商、域名/DNS、预算和主账号确认。**未授权创建云资源、绑定域名或部署服务。
>
> 关联：`00-后端总调度与阶段门禁-spec.md`、`后端框架讨论底稿.md`、`前后端接口契约.md`。

## 结论

M0 的目的不是做出一个可对外使用的后台，而是把独立 Payload 后端的架构、数据协议、安全边界、环境和团队验证路径一次明确，并以最小本地链路验证这些基础设施。项目内 Payload 依赖和本地最小链路已经验证；只有技术验收和业务 Go 同时成立后才能进入 M1 的用户功能开发。

M0 分为两个不可混淆的部分：

| 部分 | 做什么 | 当前授权 | 结束后解锁什么 |
| --- | --- | --- | --- |
| M0-A 文档与核验 | 架构、复用评估、接口和数据契约、环境/账号清单、只读前端数据盘点 | 已完成 | 提供可审阅的架构、接口冻结基线与 M1 决策材料 |
| M0-B 本地基础验证 | 固定 Node 24 与项目内依赖、Docker PostgreSQL、最小 Payload 骨架、迁移/健康检查/测试验证 | 已完成 | 证明 M1 可在受控本地基础上开发；不等于可部署团队环境 |

## 范围

### 本次要做

- 固定独立后端目录、Node 24 LTS、pnpm、Docker 和项目内 Payload 依赖的版本策略。
- 对 Payload 官方模板、认证/密码安全、S3 文件存储、限流与团队验证部署先做复用优先评估；优先下载或引用成熟、许可证和安全合格的实现，不重复自建通用能力。
- 设计本地、团队验证、生产三套隔离环境；分别隔离数据库、对象存储桶、密钥、邮件发件配置和日志。
- 固定 Web → API 的 HTTPS、CORS、Cookie、域名、健康检查和错误响应规则。
- 固定 M1 数据对象、作品 JSON 格式、文件权限、删除机制、身份和反滥用接口契约。
- 比较并在 M1 开始前由业务方确认 PostgreSQL、对象存储、邮件、托管部署的具体供应商、账号权限和预算；决策材料见 `../决策/M0-团队验证供应商与权限决策.md`。
- 已用最小本地链路验证：应用容器能连数据库、健康检查可用、迁移能运行、测试环境变量不会写入 Git。

### 本次不做

- 对外注册、真实用户、云端作品、Google 登录、邮件实际发送、公开 API、社区、订单、支付和前端改动。
- 把浏览器端的图纸生成算法迁移到后端。
- 购买生产资源或绑定生产域名；如需创建免费测试账号，先由业务方提供必要权限。

## 目标架构

```text
PixoMosaic Web（www.主域名）
        │ HTTPS + 受控 CORS
        ▼
Payload API / Admin（api.主域名）
 ├── PostgreSQL：身份、作品元数据、订单、审计、限流记录
 ├── S3 对象存储：私有原图/订单文件、受控展示图/缩略图
 └── 事务邮件：邮箱验证、密码重设、订单通知
```

- API 统一使用 `/api/v1` 作为 PixoMosaic 业务接口前缀；Payload Admin 不暴露为公共业务 API。
- Web 使用 API 子域的 `Secure`、`HttpOnly`、`SameSite=Lax` 会话 Cookie；仅允许已登记的 Web 测试/生产来源跨域携带凭据。
- 未来 App 使用独立的 Bearer Token 契约；M0 只预留，M1 不开发 App 客户端。
- 私有资源只保存对象引用；下载/读取必须经鉴权短期授权，不生成永久公开原图链接。
- 每次业务响应包含可追踪请求 ID；不在响应、日志或错误消息输出密码、令牌或私有文件路径。

## M1 数据契约基线

### 核心对象

| 对象 | M1 责任 | 关键规则 |
| --- | --- | --- |
| User | 用户身份、公开资料、状态与角色 | 邮箱唯一；角色为 `user`、`staff`、`admin`；密码只保存安全哈希 |
| TermsAcceptance | 条款、隐私版本同意记录 | 注册和涉及云端保存前必须记录版本与时间 |
| Work | 用户云端作品元数据与状态 | 每位用户最多 50 个 `active` 作品；默认私密；有 `schemaVersion` |
| WorkAsset | 原图、展示图、缩略图、导出文件引用 | 数据库只保存对象元数据和访问级别，不保存文件内容 |
| WorkDocument | 图纸格点 JSON、生成参数、色号统计、材料清单及画板快照 | 每份文档有格式版本、校验值和修订号；不可依赖前端 IndexedDB 内部键名 |
| DeletionRequest | 作品/账号删除请求与 30 天回收状态 | 前台即时不可见；到期后执行可重试删除任务 |
| AdminAuditLog | 敏感读取、角色变更、删除与后台操作记录 | 记录操作者、对象、动作、时间、结果和请求 ID；不记录敏感原文 |
| AbuseEvent | 限频、异常和封禁判断证据 | 只保存最小必要的脱敏标识和规则命中信息 |

### 作品格式与默认容量边界

- 每个作品必须保存：原图、展示图、缩略图、图纸格点 JSON、生成参数、色号统计、材料清单和导出文件引用；文件元数据由 `WorkAsset` 管理，编辑内容由 `WorkDocument` 管理。任何缺项须明确状态为“未生成”，不能以空字段伪造已完成。
- `WorkDocument.schemaVersion` 从 `1` 开始。新版本只能新增兼容读取或进行可回滚迁移，不能无提示改变旧图纸含义。
- M1 技术默认值：每作品最多 10 个源/展示相关图片；单文件最大 15 MiB；单件导出最大 20 MiB；所有附件合计最大 100 MiB；每用户总对象存储软上限 2 GiB。总调度在 M0-B 根据实际前端样本测量后可收紧，但不得放宽而不记录成本影响。
- 50 个活跃作品按用户可见且可继续编辑的作品计算；进入 30 天回收期的作品默认不计入名额，但仍计入存储软上限直到物理删除。

### M1 API 形态（只冻结用途，不在 M0 实现）

| 能力 | API 资源 | M1 最低规则 |
| --- | --- | --- |
| 注册、验证、登录、重设密码、登出 | `/api/v1/auth/*` | 邮箱验证完成前不能保存云端作品；密码和验证码不写日志 |
| 当前身份和资料 | `/api/v1/me` | 只返回前端需要的安全字段 |
| 作品列表与详情 | `/api/v1/works` | 仅所有者可读写私密作品；分页、请求 ID、统一错误码 |
| 文件上传授权 | `/api/v1/works/:id/assets/upload-intent` | 校验身份、作品归属、类型、大小和数量后才签发短期上传权限 |
| 导出资格检查 | `/api/v1/export-eligibility` | 后端参与反滥用；断网时只能由前端本地计数提供最佳努力限制 |
| 删除请求 | `/api/v1/works/:id/deletion-request` | 软删除、回收期、可恢复窗口和审计记录 |

## 身份与反滥用策略

- M1 登录为邮箱密码注册、邮箱验证、忘记/重设密码和 Google 登录；不采用仅魔法链接。
- 密码策略最小要求：至少 12 个字符；服务端使用现代自适应哈希算法；不得将密码、明文重设链接或验证码写入数据库审计日志。
- Google 身份与同邮箱密码账号不能静默合并；需验证邮箱归属或由已登录用户主动绑定，避免账号接管。
- 未登录用户的“每日 5 次导出”仍由前端显示并本地计数；后端在联网路径增加资格检查、速率限制和异常规则。离线模式无法被服务端完全阻止，属于明确的最佳努力边界。
- M1 默认速率策略：登录/注册/密码重设按 IP 与账号双维度限速；上传、作品写入与导出资格检查按用户、IP 和请求体大小限速。具体阈值以测试压测结果写入配置，不硬编码在前端。
- 第一版不引入 Redis、验证码商业服务或复杂设备指纹；异常处理先记录事件、限制短时间请求和支持 Admin 审核。

## 环境与部署策略

| 环境 | 目的 | 数据隔离 | 注册状态 |
| --- | --- | --- | --- |
| local | 开发与自动化测试 | 本地 Docker PostgreSQL、开发对象存储模拟 | 测试账号 |
| team-test | 团队验证登录、作品、权限与邮件 | 独立数据库、独立存储桶、独立邮件配置 | 邀请/白名单，不公开注册 |
| production | 正式业务 | 独立数据库、独立桶、独立密钥、备份和监控 | 初始关闭；经业务 Go 决定后开放 |

- 生产应用实例起步为 2 vCPU、4 GiB 内存、20–40 GiB 临时磁盘；数据库和文件不放入应用容器磁盘。
- 本地和云端均用 Docker 镜像发布；镜像不包含 `.env`、密钥、用户文件或数据库数据。
- 每次发布必须有健康检查、数据库迁移记录、备份状态和可回退镜像标签。

## 供应商决策规则

M0 对下列供应商做同一维度比较：月度起步成本、美国用户访问区域、数据导出与迁移、备份恢复、权限隔离、日志/监控、后续扩容和供应商锁定风险。

| 能力 | 候选 | M1 前需要冻结的结果 |
| --- | --- | --- |
| PostgreSQL | Neon、Supabase、Railway/Render 托管库 | 测试/生产实例、备份策略、连接方式 |
| 对象存储 | Cloudflare R2、AWS S3 | 私有/公开桶划分、生命周期、访问密钥范围 |
| 事务邮件 | Resend、Postmark | 发件域、退信处理、测试与生产发送策略 |
| 应用托管 | Railway、Render、Fly.io | Docker 部署、区域、日志、回滚、预算上限 |

## M0 任务顺序

1. **M0-A**：完成复用优先评估：本地资产、Payload 官方模板/插件、成熟认证、对象存储、限流和 Docker 部署方案；只下载或引用许可证、安全、活跃度和适配度合格的部分。
2. **M0-A**：建立 `docs/接口/`、`docs/决策/`、`docs/验收/` 目录与版本化文档入口，完成 ADR、API 总则、环境/账号清单。
3. **M0-A**：从 PixoMosaic 前端提取脱敏样本，定义 `WorkDocument` 的 JSON 结构、转换边界和兼容策略；不复制前端本地存储实现。
4. **M0-A**：比较供应商并提出 M1 前的账号/预算清单；付费项、域名和 DNS 权限均由业务方确认。
5. **M0-B（已完成）**：在 Node 24、pnpm、Docker PostgreSQL 下建立最小后端骨架，并验证迁移、健康检查、测试、环境变量隔离和 Docker 生产模式。
6. **M0 收尾（已完成技术部分）**：将验证证据、迁移边界和待确认供应商选择写入阶段验收记录；业务方确认 M1 Go / No-Go 前不创建云资源。

- M1 的身份、作品、文件、删除和反滥用接口用途已冻结，且未引用前端内部存储实现。
- 三套环境的隔离、密钥处理、发布、备份和回滚原则明确。
- [x] M0-B 的本地最小链路已验证应用、数据库迁移、健康检查和 Docker 生产模式；无密钥、用户数据或构建物进入 Git。
- [x] 供应商选择与 M1 所需账号/权限已形成待业务方确认的清单。
- [ ] 业务方确认 team-test 供应商主账号、域名/DNS、发件域、预算与权限后，记录 M1 Go；这不是 M0 技术未完成，而是进入付费/对外环境所需的授权。
