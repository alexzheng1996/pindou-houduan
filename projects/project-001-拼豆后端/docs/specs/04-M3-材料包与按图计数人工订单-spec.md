# Spec：M3 材料包与按图计数人工订单

> 状态：待用户审阅；仅在 M2 验收或已确认订单需求与供应链 SOP 后执行。
>
> 目标：验证用户是否愿意为材料包或按图计数服务付费，并先跑通人工确认、人工履约和可追溯状态。

## 结论

M3 不做商城或自动结账。用户从单件作品主动发起订单，后端保存不可变的材料清单快照和必要订单信息，运营人员人工确认材料、替代色、费用与交付；付款仍为线下/人工确认，不处理支付卡数据。

## 范围

### 本次要做

- 两类订单：`material_kit`（材料包）和 `bead_counting_service`（按图计数服务）。
- 从用户选定作品生成不可变材料清单快照，保留图纸版本、色号、数量、生成时间和后续人工调整原因。
- 材料包订单收集收货地址与备注；按图计数服务默认不收集地址。
- 后台人工确认缺色/替代色、包装内容、运费、人工调价、税费处理备注和最终金额。
- 订单状态、站内通知、关键邮件通知、客服备注、发货信息与操作审计。
- Admin/Staff 最小权限、地址查看审计和一次完整人工履约演练。

### 本次不做

- 在线支付、银行卡/支付凭据、购物车、独立商城、自动优惠券、自动库存扣减、自动税费、自动物流面单。
- 支付平台 Webhook、退款自动处理、批量采购、供应商自动下单。
- 成品定制、用户接单和公开展示订单图片。

## 订单规则

| 项目 | 决定 |
| --- | --- |
| 发起条件 | 用户必须登录；从一个具体作品/图纸发起一个订单 |
| 材料清单 | 创建订单时生成版本快照；后续修改只作为人工调整记录追加，不改写原始快照 |
| 地址 | 仅 `material_kit` 必填；限制美国本土 48 州，默认排除 Alaska、Hawaii 和 PO boxes；例外由 Staff 提交、Admin 审批 |
| 材料包状态 | `created → pending_confirmation → waiting_payment → preparing → shipped → delivered → completed`，或 `canceled / refunded` |
| 按图计数状态 | `created → pending_confirmation → waiting_payment → processing → delivered → completed`，或 `canceled / refunded` |
| 付款 | 只记录人工确认状态、方式、时间、外部参考号和退款状态；不保存银行卡、支付截图中的敏感内容或支付账户凭据 |
| 调价 | 最终金额、运费、优惠/客服补偿和调整原因均需记录操作者和时间 |
| 通知 | 报价/人工确认、待付款、状态变化、发货、取消和退款发送站内通知与事务邮件 |

## 隐私与后台权限

- 收货地址、订单备注、原图和定制前资料均为私密数据；Staff 仅在处理已分配订单时读取，Admin 可审计访问。
- 所有状态变化、地址读取、价格调整、发货录入和退款标记写入审计日志。
- 用户可查看自己的订单、材料清单快照、当前状态、最终确认金额和已公开的发货信息；不能读取内部成本、员工备注或其他用户数据。

## 验收标准

- 登录用户能从单件作品发起材料包或按图计数订单；未登录和越权用户不能访问订单。
- 材料清单快照与作品版本可追溯，人工调整有原因、操作者与时间。
- 地址仅对材料包收集，地域限制生效，读取地址和敏感订单资料均有审计。
- Staff 可按权限确认订单、修改允许状态、记录发货；Admin 可处理例外、退款和敏感操作。
- 站内与邮件通知覆盖关键状态，失败可重试且不重复发送。
- 完成至少一次“发起 → 人工确认 → 人工付款确认 → 履约/交付 → 完成”的演练，并记录成本、时间、异常与复盘。

## 进入 M4 的门禁

- 至少一条人工订单路径可稳定履约，订单/地址权限与通知没有高风险缺陷。
- 业务方确认定制服务的报价口径、制作责任、发货时效和售后承诺可承担。
