# Spec：PixoMosaic 后端总调度与阶段门禁

> 状态：待用户审阅。本文是后端项目的总执行规则；它不授权安装依赖、创建云资源或开发业务功能。
>
> 适用范围：`project-001-拼豆后端` 的 M0 至 M4；PixoMosaic 前端仓库不在本文执行范围内。

## 结论

后端按 M0 → M1 → M2 → M3 → M4 串行推进。每阶段需要同时通过技术验收和业务 Go / No-Go，才允许总调度创建下一阶段的实施任务；不把“能开发”当作“应继续投入”。

## 已确认的基础边界

- 技术组合：独立 Payload 后端 + PostgreSQL + S3 兼容对象存储 + 事务邮件 + Docker + 托管部署。
- 后端与 PixoMosaic 前端为独立仓库，通过 HTTPS API 契约协作；未经明确授权不修改前端仓库。
- 本地免费工具和浏览器端图纸生成继续留在前端；后端只承接登录、云端、社区、订单、后台与安全边界。
- M1 是账号与云端作品；每位用户最多 50 个活跃作品，保存原图、展示图、缩略图、图纸 JSON、生成参数、色号统计、材料清单及导出文件。M1.1 作为 M1 受控扩展，提供个人豆仓、图纸库存状态和用户确认后的制作扣减；它不属于 M2 社区或 M3 店铺库存。
- M2 只能在 M1 验收后开始；M3 为材料包与按图计数人工订单；M4 为定制成品服务。
- 第一版不做在线支付、购物车、自动库存、自动物流、评论、私信、自动图片审核与 App 客户端。
- 先在本地完成并验证 M1 最小功能；仅在部署前检查通过且业务方再次 Go 后，才建设团队验证环境。团队验证后再决定是否开放生产注册。

## 总调度职责

总调度是后端项目唯一的执行编排入口，不是新的系统或长期独立线程。它在每个已获批准阶段开始时执行以下动作：

1. 读取该阶段 Spec、接口契约、上一阶段验收、全局踩坑日志及 Git 状态。
2. 对复杂设计、通用能力、第三方集成和自动化先做“复用优先评估”：检查本地资产/skill、成熟开源项目、官方模板和轻量服务，记录成熟度、适配度、许可证、安全、接入和维护成本。
3. 对耗时长、边界清晰的任务包安排子代理并行协助，例如资料筛选、成熟方案核验、代码检查、测试验证或长文档拆读；不为轻量任务强行并行。
4. 拆分可独立验收的任务包：数据模型、API、后台权限、前端联调、自动化测试、文档和交接。
5. 为每个任务包固定目标、范围/不做项、前置依赖、接口影响、验收证据、迁移与回滚要求；若选择复用，另写明精确引用/下载来源、复用部分和明确不引入部分。
6. 主线程回收所有子代理结果并交叉检查、去重和合并；架构决策、敏感信息、账号权限、数据口径、业务承诺和最终验收由主线程负责。
7. 只在前置任务验收通过后安排后续任务；跨仓库工作以接口契约为准，不读取或修改前端内部状态来替代契约。
8. 阶段结束汇总交付、未交付、测试、风险、成本变化和下一阶段进入建议，交由业务方做 Go / No-Go。

### 总调度可自行决定

- 在已批准 Spec 内选择最简单、可测试、可回滚的代码结构和依赖顺序。
- 任务拆分、测试数据、错误码细节、日志字段、重试策略和文档组织。
- 在复用评估通过后，下载或项目内引入成熟依赖、模板、组件或示例，并做许可证、安全与版本锁定检查。
- 不改变业务承诺前提下的文件大小、速率和存储成本技术默认值；改动需记录版本影响。

### 总调度必须上报

- 域名、付费供应商、预算、生产地域与账号权限选择。
- 创建任何 team-test 云资源前的预估月费用、免费额度、预算上限、停止/删除方案和不可逆影响；未获业务方当次明确 Go，不得开户、部署、写入 DNS 或配置真实 OAuth/邮件。
- Privacy Policy、Terms of Service、退款/取消规则、投诉入口和对外数据承诺。
- 支付、税费、物流、自动化履约、App 接入或任何超出当前阶段的新功能。
- 任何涉及更多个人数据、放宽文件访问、缩短/延长保留期限或降低安全门槛的变更。

## 标准任务包格式

```markdown
# <阶段>-<编号>-任务名

## 目标
## 范围与不做项
## 前置依赖
## 接口与数据影响
## 实施约束
## 验收证据
## 迁移与回滚
## 交接输出
```

如任务涉及复用，增加：

```markdown
## 复用优先评估
- 候选与来源：
- 成熟度、许可证与安全检查：
- 复用/改造部分：
- 明确不引入部分：
- 不采用其他候选的原因：
```

任务只允许在对应阶段的 `docs/`、`src/`、`tests/`、`scripts/`、`logs/`、`output/`、`handoff/` 中产生长期文件。构建物、下载物和调试文件必须在收尾前归入项目目录或删除。

## 阶段验收记录

每阶段完成后，总调度应在 `docs/验收/阶段验收记录.md` 追加：阶段编号、运行版本、执行日期、已验证清单、未完成项、风险、回滚点、业务 Go / No-Go 决定与确认人。未记录验收不得开始下一阶段。

## 验收标准

- M0–M4 的范围、依赖、门禁和不做项可被单独引用，不需要回看聊天记录。
- 总调度的授权边界明确：技术细节可自行收敛，商业、合规、预算和对外承诺必须上报。
- 后续阶段任务可以按本 Spec 创建，且不会把前端仓库、支付或超前功能混入当前阶段。
