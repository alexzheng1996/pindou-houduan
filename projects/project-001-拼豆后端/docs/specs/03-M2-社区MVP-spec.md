# Spec：M2 社区 MVP（用户发布与社区互动）

> 状态：待用户审阅；仅在 M1 验收与业务 Go 后执行。
>
> 目标：验证用户是否愿意发布、浏览和互动。运营治理后台已拆到 `M2.2-社区治理后台-spec`，官方教程/博客已拆到 `M2.1-官方内容中心与SEO-GEO-spec`。

## 结论

M2 把已验证用户的作品变成“发布即公开”的社区帖子。用户侧先完成公开展示、点赞、收藏、复制和举报；运营事后治理由 M2.2 处理。评论、私信和自动图片审核全部延后。

## 范围

### 本次要做

- 公开帖子、多图发布（每帖最多 9 张）、帖子详情、公开作者主页。
- 用户社区资料可维护社交媒体链接，并可对每条链接分别选择公开或隐藏。
- 社区首页的“最新”和基于互动数据的基础排序。
- 点赞、收藏；不实现作者关注。
- 作者主动控制图纸复制授权；记录授权状态与操作证据。
- 举报、作者主动撤回、公开安全投影和敏感操作审计；运营处理队列、精选、下架、备注和特别关注见 M2.2。

### 本次不做

- 评论、回复、私信、外链、联系方式、用户互相接单、创作者分成、作者关注。
- 发布前人工逐条审核、图片自动识别审核、复杂推荐和搜索排序。
- 已发布帖子替换图片、批量导入外部内容、App 客户端。

## 关键规则

| 主题 | 规则 |
| --- | --- |
| 发布资格 | 仅已验证注册用户可发布；帖子从自己的 active Work 发布，帖子创建成功即为公开 `published` |
| 图片 | 每帖最多 9 张；发布后不能替换图片，只能改标题、分类、标签和复制授权开关；撤回使用独立操作 |
| 可见性 | 发布即公开并生成公开 URL；作者可主动撤回；私密作品原图不会因发布而自动公开 |
| 分享 | 只要帖子状态为 `published`，公开 URL 自动具有分享资格并显示分享按钮；作者无需逐帖另行授权，撤回、下架或删除后立即失效 |
| 社交资料 | 用户可维护 Instagram、TikTok、YouTube、Pinterest、Facebook、X、Reddit、LinkedIn 的 HTTPS 主页链接；每个平台最多一条，默认隐藏，逐条选择 `public|hidden` |
| 社交资料公开投影 | 作者公开页和社区帖子作者区只返回 `public` 链接；`hidden` 链接不进入匿名响应、分享图、SEO/GEO、结构化数据或 MCP |
| 授权 | 图纸复制默认关闭；作者主动开启；每次操作记录当时授权状态和图纸版本 |
| 互动 | 同一用户对同一对象只能有一条点赞或收藏记录；撤销应幂等 |
| 内容治理 | 作者撤回后立即隐藏。运营下架、删除、封禁和精选由 M2.2 执行 |

## 数据与隐私要求

- 公开页只显示昵称、头像、简介、公开帖子和允许展示的互动统计；不显示邮箱、订单、私密作品或原图。
- 公开展示使用经授权的展示图/缩略图；私密原图仍保留受控访问。
- 举报、版权/隐私投诉、处理原因、处理人和通知结果需保存审计记录；公开页不暴露举报人身份。
- 用户删帖遵循 M1 的 30 天回收逻辑；被平台下架的记录保留到处理结束和必要的争议窗口。
- 用户发布即公开不代表作品图纸、原图或生成参数自动公开；公开接口只返回社区冻结版本和独立社区媒体。
- “公开”同时是对公开 URL 被访客转发的同意；它不等同于允许平台设为精选、搜索收录，或改编为官方文章。
- 社交资料的“隐藏”只表示不对访客公开，不表示从本人资料或 Staff/Admin 后台删除；M2.2 后台必须完整显示真实链接并标注 `隐藏`。后台对该用户的全部社区帖子、冻结发布内容、社区媒体和治理档案同样可完整读取；这不扩展为未发布私密 Work/原图、邮箱、密码、会话、Token、订单、支付或地址可见。

## 验收标准

- 未登录用户只能浏览公开内容；已注册用户能发布、编辑允许修改的字段，并控制下载/复制授权。
- 一名用户不能修改另一名用户的帖子、授权或互动记录。
- 点赞、收藏、撤销和重复请求的结果正确且可审计；不存在作者关注接口。
- `published` 帖子自动有分享按钮；作者撤回、运营下架或删除后，分享按钮和外部分享 URL 立即不可用。
- 用户可新增、修改、删除自己的社交链接并逐条切换 `public|hidden`；匿名作者页只返回公开项，隐藏项不通过 URL、缓存、SEO/GEO 或页面源码泄露。
- 举报、作者撤回、私密数据隔离和公开页隐藏路径均可验证；M2.2 单独验证运营下架、精选、违禁词配置和治理队列。
- 私密文件、地址、邮件和订单信息不通过社区 API 或页面泄露。
- 运营治理后台的进入条件是 M2.2 Spec 已批准并有运营处理人。

## 进入 M3 的门禁

- 社区治理能被运营人员稳定执行，不需要技术人员手工改数据库处理违规。
- 有实际或明确可验证的材料包/按图计数服务需求，且供应链已准备人工履约 SOP。
