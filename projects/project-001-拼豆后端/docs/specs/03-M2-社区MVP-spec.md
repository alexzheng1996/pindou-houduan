# Spec：M2 社区 MVP 与内容治理

> 状态：待用户审阅；仅在 M1 验收与业务 Go 后执行。
>
> 目标：验证用户是否愿意发布、浏览和互动，同时建立最低可用的内容治理闭环。

## 结论

M2 把已注册用户的作品变成“可选择公开发布”的社区帖子。社区第一版追求可控的展示、互动和举报，不追求活跃功能堆叠；评论、私信和自动图片审核全部延后。

## 范围

### 本次要做

- 公开帖子、多图发布（每帖最多 9 张）、帖子详情、公开作者主页。
- 社区首页的“精选”和“最新”两种排序。
- 点赞、收藏、关注作者。
- 作者主动控制图纸下载和生成参数复制授权；记录授权状态与操作证据。
- 后台推荐标签、用户自定义标签、基础英文违禁词拦截。
- 举报、立即下架、隐藏、删除、封禁、`noindex`、处理队列、用户通知和敏感操作审计。
- Admin/Staff 治理权限与联调/自动化测试。

### 本次不做

- 评论、回复、私信、外链、联系方式、用户互相接单、创作者分成、关注标签。
- 图片自动识别审核、发布前人工逐条审核、复杂推荐和搜索排序。
- 已发布帖子替换图片、批量导入外部内容、App 客户端。

## 关键规则

| 主题 | 规则 |
| --- | --- |
| 发布资格 | 仅已验证注册用户可发布；帖子可关联作品，但不强制关联完整图纸 |
| 图片 | 每帖最多 9 张；发布后不能替换图片，只能改标题、说明、标签、公开状态与授权开关 |
| 可见性 | 默认不公开；作者主动发布后才生成公开 URL；私密作品原图不会因发布而自动公开 |
| 授权 | 下载图纸和复制参数默认关闭；作者主动开启；每次操作记录当时授权状态和图纸版本 |
| 互动 | 同一用户对同一对象只能有一条点赞、收藏或关注记录；撤销应幂等 |
| 内容治理 | 违禁词命中阻止发布；举报、下架、删除或封禁后立即前台隐藏；必要时加 `noindex` |
| 后台权限 | Staff 处理分配的举报、下架、精选与订单外内容；删除、封禁、违禁词库和系统配置仅 Admin |

## 数据与隐私要求

- 公开页只显示昵称、头像、简介、公开帖子和允许展示的互动统计；不显示邮箱、订单、私密作品或原图。
- 公开展示使用经授权的展示图/缩略图；私密原图仍保留受控访问。
- 举报、版权/隐私投诉、处理原因、处理人和通知结果需保存审计记录；公开页不暴露举报人身份。
- 用户删帖遵循 M1 的 30 天回收逻辑；被平台下架的记录保留到处理结束和必要的争议窗口。

## 验收标准

- 未登录用户只能浏览公开内容；已注册用户能发布、编辑允许修改的字段，并控制下载/复制授权。
- 一名用户不能修改另一名用户的帖子、授权或互动记录。
- 点赞、收藏、关注、撤销和重复请求的结果正确且可审计。
- 违禁词拦截、举报、Staff 下架、Admin 删除/封禁及公开页 `noindex` 路径均可验证。
- 私密文件、地址、邮件和订单信息不通过社区 API 或页面泄露。
- 运营人员可按清晰队列处理违规内容，并完成一次端到端举报处理演练。

## 进入 M3 的门禁

- 社区治理能被运营人员稳定执行，不需要技术人员手工改数据库处理违规。
- 有实际或明确可验证的材料包/按图计数服务需求，且供应链已准备人工履约 SOP。
