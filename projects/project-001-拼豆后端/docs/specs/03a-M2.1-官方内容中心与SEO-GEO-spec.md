# Spec：M2.1 官方内容中心与 SEO/GEO

> 状态：待用户审阅；本文只定义规格，不授权现在开发、部署、连接搜索平台或社交平台账号。
>
> 目标：建立可人工审核的官方英文内容中心，分别承载网站工具教程与创意/产品内容，并为后续 SEO、GEO、公开分享和品牌视频提供稳定的后端数据边界。

## 1. 结论

保留两个公开入口，但共用一套文章数据模型、媒体边界和审核流程：

| 入口 | 内容定位 | 推荐 URL |
| --- | --- | --- |
| Guides | 网站工具使用教程和操作指引，例如照片转图纸、尺寸选择、导出和制作流程 | `/guides/[slug]` |
| Blog | 创意内容、产品教程、主题案例、品牌内容和活动更新 | `/blog/[slug]` |

Codex 只生成或更新草稿；草稿在后台对 Staff/Admin 可见，人工审核通过后才能发布。发布后公开，但不意味着可以自动发布到 TikTok、YouTube 或其他社交平台。

## 2. 范围

### 2.1 本次要做

- 官方文章集合、文章媒体集合、受控视频块和后台草稿/审核流。
- `/guides`、`/guides/[slug]`、`/blog`、`/blog/[slug]` 的公开读取契约。
- 英文标题、摘要、canonical、Open Graph、Twitter/X 卡片、sitemap、robots、`noindex` 和结构化数据基础。
- 官方文章分享按钮，以及所有仍公开的社区帖子分享入口；精选社区案例自动进入 SEO 收录。
- 品牌自有 YouTube/TikTok 视频的受控嵌入和站内观看；视频故障时保留正文和外链回退。
- 只创建/更新草稿的 Codex/MCP 能力、最小权限、审计和未来 scope 预留。

### 2.2 本次不做

- AI 自动发布、自动下架、自动精选或绕过人工审核。
- 代表运营账号向 TikTok、YouTube、Facebook 等平台直接发帖。
- 普通用户向官方内容中心投稿，或在社区帖子中提交任意 iframe、HTML、脚本。
- 自动接入 Search Console、GA4、Bing Webmaster、社交 OAuth 或创建云资源。
- 以 GEO 作为排名保证；不伪造评分、评论、作者资质、引用或视频信息。

## 3. 角色与权限

| 角色 | 草稿 | 审核 | 发布/归档 | SEO 元数据 | 视频块 | MCP |
| --- | --- | --- | --- | --- | --- | --- |
| 普通用户 | 无 | 无 | 无 | 无 | 无 | 无 |
| Staff | 创建、编辑、查看 | 审核、退回修改 | 按后台授权发布、归档 | 编辑并校验 | 添加已授权品牌视频 | 不使用个人账号调用 |
| Admin | 全部 | 全部 | 全部 | 全部 | 全部 | 管理服务身份和 scope |
| Codex/MCP 服务身份 | 创建/更新 `draft` | 不可批准 | 不可发布、归档或下架 | 可写草稿中的建议字段 | 仅写入受控字段 | 只能使用短期最小权限 |

所有角色校验在服务端完成；不信任请求体中的 `role`、`authorId`、`status` 或 `publishedAt`。

## 4. 内容模型

### 4.1 Article

文章使用独立的 `Article` 集合，不与 `CommunityPost`、`Work`、`WorkDocument` 或 `WorkAsset` 共用原始记录。

| 字段组 | 字段与规则 |
| --- | --- |
| 标识 | `publicId`、`section=guides|blog`、唯一英文 `slug`、版本号 |
| 内容 | `title`、`excerpt`、受控 Markdown/富文本正文、`articleType` |
| 类型 | Guides 首选 `tool_guide|faq`；Blog 可用 `creative|product_tutorial|case_study|announcement` |
| 作者 | `authorType=staff|codex_assisted`、作者展示名、审核人、来源说明 |
| 媒体 | `coverMediaId`、正文图片引用、受控 `videoBlock`；媒体来自文章专用命名空间 |
| 状态 | `draft|in_review|changes_requested|scheduled|published|needs_update|archived` |
| 时间 | `scheduledAt`、`publishedAt`、`updatedAt`、`nextReviewAt` |
| 案例 | 可选 `communityPostId`；必须指向已公开、额外授权且运营批准的安全投影 |
| 质量 | 选题意图、来源/引用清单、编辑备注、事实核查状态 |

同一主题不得在 Guides 和 Blog 复制近似正文。实现时用 slug/主题相似度检查提示编辑者，最终由人工判断；提示不能替代审核。

### 4.2 SEO 字段

`seoTitle`、`metaDescription`、`canonicalUrl`、`ogImageMediaId`、`twitterCard`、`indexable`、`noindexReason`、`primaryTopic`、`relatedArticleIds`。`canonicalUrl` 默认只能指向本站允许的公开 URL，外部 canonical 需要 Admin 明确批准并记录原因。

官方文章公开发布前必须完成：英文 title/description、稳定 slug、canonical、分享图、作者/更新时间和内容正文检查。官方文章的 `indexable=true` 仍由人工编辑决定；社区案例不在这里手工配置，而由 M2.2 的“仍公开且精选”规则自动派生。

### 4.3 受控视频块

文章只保存结构化视频数据，不保存编辑者提供的 iframe/HTML/脚本：

| 字段 | 规则 |
| --- | --- |
| `platform` | 第一版仅 `youtube` 或 `tiktok` |
| `videoId` / `sourceUrl` | 服务端解析并校验官方域名、ID 格式和品牌允许的频道/账号 |
| `title`、`summary`、`caption` | 必填文字语义；视频不能替代正文 |
| `thumbnailUrl`、`durationSeconds`、`publishedAt` | 只有真实且有权使用时填写 |
| `ownership=brand_owned` | 第一版必须为品牌自有视频；不得用普通用户视频 |
| `externalUrl` | 播放失败时的官方外链回退 |
| `embedAllowed` | 平台允许嵌入且通过审核时才为 true |

前端按 `platform` 生成固定播放器，部署时通过 CSP `frame-src` 白名单限制来源。默认点击后加载、禁止自动播放；页面必须先显示标题和文字摘要。

## 5. 状态流转与审核

```text
draft → in_review → scheduled → published → needs_update → archived
             ↘ changes_requested ↗
```

- Codex/MCP 创建或更新只能产生 `draft`，不能伪造 `in_review` 以上状态。
- Staff/Admin 提交审核时执行字段、链接、来源、媒体、SEO 和版权检查。
- 退回修改必须有原因；修改后回到 `draft`，不能保留旧的审核通过标记。
- `published` 只由人工后台操作产生，保存操作者、时间、版本和理由。
- 修改已发布正文、canonical、indexable、分享图或视频授权时，记录变更并可要求重新审核。
- `archived` 页面从导航和 sitemap 移除；是否返回 `410` 由上线时的删除策略决定，不能以 `robots.txt` 代替处理。

## 6. 公开页面和分享

### 6.1 公开页面

- 列表只读取 `published` 且满足公开时间的文章。
- 详情页使用英文 SSR/预渲染，首屏不依赖编辑器或第三方播放器脚本。
- `/guides` 和 `/blog` 分别输出列表 title、description、canonical 和分页规则；详情页输出 Article、BreadcrumbList 及可见 FAQ 的结构化数据。
- 草稿、审核中、排期前、归档和下架页面不进入公开导航、sitemap 或推荐位。

### 6.2 分享按钮

分享的目标是分享当前公开 URL，不是代替用户发帖。按钮出现在：

1. 已发布官方文章；
2. 所有仍为 `published` 的社区帖子。

第一版提供复制链接、浏览器 Web Share，以及 Facebook、X、Pinterest、Reddit、LinkedIn、WhatsApp、Telegram 等公开分享入口。TikTok/YouTube 只提供复制链接或系统分享，不显示“发布到 TikTok/YouTube”。

分享参数只包含公开 URL、编码后的 title/description 和文章或社区公开媒体生成的分享图；不带邮箱、私密 Work ID、对象存储键或用户私密参数。可附标准 UTM，但 canonical 永远指向不带 UTM 的干净 URL。帖子撤回、运营下架或删除后，分享配置立即不再返回。

### 6.3 社区案例的派生公开规则

社区帖子不保存可被人工误配的 `externalShareAllowed` 或 `indexable` 开关，而是由当前公开状态派生：

- `shareable = (status === published)`：所有公开帖子自动可分享；
- `indexable = (status === published && isFeatured === true)`：运营设为精选时自动进入 SEO/GEO 收录、sitemap 与对应结构化数据；
- 取消精选只移除站内推荐和 SEO/GEO 收录，不影响帖子仍公开时的分享资格；撤回、下架或删除同时使两项派生权限失效。

如需把用户帖子改编为官方 Guides/Blog 文章，仍须有额外的内容改编授权；这与用户允许公开分享及精选 SEO 是不同的用途。

## 7. SEO/GEO 架构

### 7.1 首发技术基线

- 每个公开页面有唯一英文 `title`、description、canonical、Open Graph/Twitter 卡片和可读 URL。
- `sitemap.xml` 只列已发布且 `indexable=true` 的官方文章，以及仍为 `published` 的精选社区案例；取消精选、撤回、下架、归档或删除后同步移除。
- `robots.txt` 只声明抓取路径，不能替代登录访问控制、`noindex` 或删除语义。私密页需访问控制并输出 `noindex`。
- 结构化数据必须与页面可见内容一致：`WebSite`、`SoftwareApplication`、`Article`、`BreadcrumbList`、可见 FAQ，以及信息完整时的 `VideoObject`。
- 图片使用真实英文 alt、压缩和固定尺寸；绝不把用户私密原图或私有 URL 放入公开元数据。
- 用户资料中的公开社交链接属于用户生成外链：公开页仅可显示用户主动设为 `public` 的链接，并使用 `rel="ugc nofollow noopener noreferrer"`；隐藏链接绝不输出。第一版不把用户社交链接写入结构化数据的 `sameAs`，也不把它们当作官方背书或 GEO 依据。
- 工具编辑器和第三方播放器按需加载，保证正文首屏和 Core Web Vitals。

### 7.2 GEO 内容要求

GEO 依赖可引用、可理解、可验证的公开内容，而不是独立的“排名插件”。每篇文章应：直接回答一个真实问题；给出步骤、限制、例子和适用人群；列出来源/引用；注明作者、审核人和更新时间；说明 PixoMosaic 的能力边界及照片隐私处理。`llms.txt` 只在公开内容稳定后评估，不能替代正常 SEO、SSR、sitemap 或结构化数据。

### 7.3 衡量与隐私

上线后再分别接入 Search Console、Bing Webmaster 和 GA4，数据口径分开。最小事件可包含 `content_share_clicked`（内容 ID、渠道、时间），不得包含邮箱、照片内容或私密用户标识。营销订阅与条款同意分开，营销默认不勾选并支持退订。

## 8. Codex/MCP 草稿接口边界

### 8.1 允许

- 读取内容规范、选题池、已发布文章的公开投影和无敏感内链目录；
- 创建文章草稿；
- 更新自己创建或被授权接管的草稿；
- 写入来源清单、FAQ、内链建议、视频脚本建议和 SEO 建议字段；
- 提交“请求人工审核”的建议，但不改变审核状态。

### 8.2 禁止

- 直接发布、排期、归档、下架、精选或改 `indexable`；
- 读取用户邮箱、会话、私密 Work、私密原图、对象存储键、举报内容或运营内部备注；
- 代表任何账号向 TikTok、YouTube 或其他社交平台发布；
- 使用长期高权限 Token，或把凭据写入内容、日志、提示词和响应。

### 8.3 未来扩展点

可为未来版本预留独立 scope，例如 `content:draft:create`、`content:draft:update`、`content:review:request`。当前不创建 `content:publish`、`content:takedown` 或 `content:feature` scope。未来扩权必须重新 Spec、做安全/权限审查、通过验收并取得业务方单独授权。

## 9. 拟定接口

具体 URL 可在实现阶段冻结，但不得突破以下语义：

| 接口 | 权限 | 作用 |
| --- | --- | --- |
| `GET /api/v1/content/articles` | 公开 | 按 section 读取已发布文章列表 |
| `GET /api/v1/content/articles/:slug` | 公开 | 读取公开详情和安全媒体投影 |
| `GET /api/v1/content/sitemap` | 公开爬虫 | 返回可收录 URL 集合 |
| `GET /api/v1/admin/content/articles` | Staff/Admin | 后台筛选、编辑和审核 |
| `POST /api/v1/admin/content/articles` | Staff/Admin | 创建后台草稿 |
| `PATCH /api/v1/admin/content/articles/:id` | Staff/Admin | 编辑草稿或受控更新 |
| `POST /api/v1/admin/content/articles/:id/review` | Staff/Admin | 通过、退回、排期或人工发布 |
| `POST /api/v1/mcp/content/drafts` | MCP draft scope | 创建草稿 |
| `PATCH /api/v1/mcp/content/drafts/:id` | MCP draft scope | 更新草稿 |

所有写操作沿用现有 trusted Origin、会话/服务身份、幂等、请求 ID、限流、审计和错误码规则。

## 10. 验收标准

- `/guides` 与 `/blog` 能分别展示正确定位的已发布文章，且不能用同一篇文章伪装两个入口。
- Codex 创建的草稿可在后台被 Staff/Admin 找到、编辑和审核；Codex 调用无法改变为 `published`。
- 未审核文章无法从公开 URL、导航、sitemap 或结构化数据读取。
- 发布页具有独立 title、description、canonical、OG/Twitter 图和符合可见内容的 JSON-LD；含 UTM 的访问仍输出干净 canonical。
- 分享按钮出现在已发布官方文章和所有 `published` 社区帖子；TikTok/YouTube 不被描述为自动发布。
- 品牌自有 YouTube/TikTok 视频以受控块站内观看；禁止任意 iframe/HTML/脚本；视频失败时正文和官方外链仍可用。
- 社区帖子处于 `published` 时自动可分享；设为精选时自动进入 SEO/GEO 收录，取消精选时只移除收录；撤回、下架或删除时分享按钮和 sitemap 均正确收敛。
- 公开响应不包含邮箱、私密 Work、原图、对象存储键、运营备注或长期 Token。

## 11. 进入实现前的门禁

- 用户批准本 Spec 和对应接口契约；
- 明确英文内容负责人、审核人和案例授权文本；
- 明确站点主域名、隐私/条款、视频品牌账号和内容媒体存储边界；
- 完成复用评估、前后端接口版本冻结和测试数据设计；
- 不在未获批准前创建云资源、接入搜索平台或修改 PixoMosaic 前端仓库。
