# Spec：M4 定制成品服务

> 状态：待用户审阅；仅在 M3 验收与业务 Go 后执行。
>
> 目标：用私密、可追溯的流程验证成品定制是否有足够价值覆盖沟通、制作、发货与售后成本。

## 结论

M4 是平台自行承接的定制服务，不是用户互相接单市场。用户提交图片与需求，后台人工审核、报价和推进履约；第一版不自动报价、不自动收款，也不向社区公开定制内容。

## 范围

### 本次要做

- 私密定制需求：图片、目标尺寸、用途、预算、期望交付物和备注。
- 后台审核可行性、侵权/内容风险、报价、客服备注和用户确认报价。
- 状态机、制作/发货记录、站内/邮件通知、文件权限和审计。
- 拒绝、取消、退款状态和原因记录。
- 一次完整定制履约演练与利润/沟通成本复盘。

### 本次不做

- 用户接单、自由报价市场、公开展示定制订单、自动设计/自动报价、在线支付、自动售后、复杂排产。
- 未经业务方确认的任何交期、价格、素材版权或可制作承诺。

## 关键规则

| 项目 | 决定 |
| --- | --- |
| 提交资格 | 用户必须登录；需求与文件默认私密，不进入社区 |
| 状态 | `submitted → reviewing → quoted → waiting_payment → in_progress → shipped → completed`，或 `canceled / refunded` |
| 报价 | Staff 可录入草案；对外最终报价、例外折扣和退款由 Admin 审核并留痕 |
| 图片与版权 | 用户提交时确认拥有必要使用权；后台可拒绝明显侵权、名人肖像、商标或禁止内容 |
| 文件访问 | 仅订单用户、分配 Staff、Admin 按最小权限读取；读取、下载和状态变化可审计 |
| 履约 | 配送地域和危险提示沿用材料包规则；具体承诺以业务方确认的 SOP 为准 |
| 付款 | 继续采用人工确认，不保存支付敏感数据；在线支付是后续独立阶段 |

## 验收标准

- 用户能私密提交需求，查看自己的报价、状态和通知；不能访问其他用户文件或订单。
- 后台能审核、拒绝、报价、记录用户确认、推进制作/发货或取消/退款，并留下完整审计。
- 文件、客服备注、报价草案和内部成本不泄露到社区或非授权用户。
- 完成至少一笔端到端定制履约演练，并复盘沟通时长、材料成本、制作成本、发货成本、售后风险和实际毛利。
- 业务方根据演练决定是否扩大定制服务、保持限量入口或收缩回 M3 的标准化商品。
