## 需在冻结时一并澄清的高优先级事项

| 事项 | 观察到的事实 | 建议确认点 |
| --- | --- | --- |
| 双重修订号 | 顶层已有 `documentRevision`，画板示例又有未说明用途的 `board.revision`。当前前端草稿 `revision` 是本地共享草稿冲突控制的一部分。 | 保留一种业务修订号，或明确两者不同用途；避免前端把本地草稿 revision 上传为云端并发控制。 |
| `PixelCell.key` 语义 | 前端普通生成时 `key` 是当前色板的代码，CSV 导入时可为 HEX；显示色号又是由 `color + selectedColorSystem` 派生。 | 明确服务端是否只以 `color` 作为统计/替换真值，`key` 是可校验的来源信息还是仅兼容字段；避免不同导入路径被误拒。 |
| 原图与再生成能力 | 当前普通图片图层从 `sourceImageSrc` 再生成；模板图层不允许走同一再生成路径。契约允许 `sourceAssetId` 可选。 | 每类资产状态要说明“可继续再生成 / 仅可继续编辑矩阵 / 原始文件不可用”的界面与 API 表达，不能把可选引用理解为永远可再生成。 |
| 保存所需的资产角色 | M0/M1 文档一处写“每作品必须保存”原图、展示图、缩略图和导出文件，另一处又允许未生成状态；当前 CSV 导入没有原图，现有导出也可仅在浏览器生成。 | 按作品类型定义 `required`、`optional`、`not_generated`；特别明确首次保存是否必须同步生成展示图/缩略图/导出文件。 |
| 前后端限制不一致 | 前端图片输入限制为 20 MiB，M1 服务端计划限制为 15 MiB；前端单图 CSV/完整整板编辑保护为 90,000 格，但画板尺寸 UI 可达 4,000,000 格。 | 选定服务端权威限制后，前端在上传/保存前显示同一限制并正确处理拒绝；限额不能仅写在后端文档。 |
| 作品数量口径 | 当前 M0/M1 规定每用户 50 个 active 作品；前端商业化 PRD 仍写“建议默认 100 个，后台可调整”。 | 在 M1 验收与前端文案前由业务方确认一个正式值，并记录是否配置化；否则验收标准不唯一。 |
| 内容哈希 | 契约要求后端重算内容哈希，但未说明规范化方式、算法输出用途或是否返回。 | 若用于去重/审计/缓存，需固定算法和规范化规则；若仅内部审计，应明确前端不依赖其值。 |

## 建议的 M0-B 核查顺序（非实现顺序）

1. 先写并用两份脱敏样本验证前端转换器：`pattern` 2×2；`board` 4×3（图片层、模板层、`inherited`/`final` 直接补色、擦除和颜色替换）。
2. 同时确定资产角色矩阵和首次保存时序，覆盖图片导入、CSV 导入、模板导入和无导出文件的首次保存。
3. 用接近上限的合成样本测量大小，再把限制写入服务端配置、JSON Schema、API 错误码与前端提示。
4. 最后冻结 endpoint 示例、修订冲突和幂等行为，并以 API 自动化测试和一次前端跨设备读取作为 M0 证据。
