### 真实浏览器闭环（本机 HTTP，不是 team-test）

1. A 用户：注册 → OTP 验证 → 登录 → 进入 `/inventory` → 入库 `2.6mm/#FAF4C8 +100` → 页面显示 100/正常。
2. A 用户：删除入库记录 → 接口返回 200 → 页面显示余额 0/缺货，原入库记录隐藏，回滚记录保留。
3. A 用户：上传 2×2 PNG → 生成图纸 → 填写名称 → “保存云端” → `POST /works` 201、`PATCH /document` 200、页面显示云端版本 1。
4. A 用户：点击“完成制作并扣减” → 服务端重新读取清单 → 浏览器确认框 → `POST /complete` 200 → 页面显示扣减结果和回滚提示。
5. A 用户：在豆仓删除制作记录 → `DELETE /operations/:id` 200 → 两种颜色余额恢复为 0，回滚记录保留。
6. B 用户：独立浏览器会话注册/验证/登录 → `/inventory` 显示“尚无符合条件的库存” → `/board` 的“云端作品”显示“还没有云端作品”，无法看到 A 数据。

结论：以上注册登录、库存导入（逐色入库和 CSV 预检）、作品保存、制作扣减、回滚和 A/B 隔离已通过真实浏览器本机 HTTP 验证；该结论不称为 team-test/生产完整前后端联调。真实邮件、真实 Google OAuth、team-test 和 DNS 仍不宣称通过；缺货清单下载按钮未在本轮重复做浏览器点击。
