## 当前已知前端能力（仅作协作背景）

PixoMosaic 已具备图片转拼豆图纸、颜色映射、画板编辑、导出和本地草稿等前端能力。M1 已确认跨设备保存单图图纸与画板快照；M1.1 已确认个人豆仓按底层 HEX + 规格归属，具体字段和转换边界见 `接口/M1-作品数据契约.md` 与 `specs/02e-M1.1-个人豆仓与制作扣减-spec.md`。浏览器 IndexedDB/localStorage、Data URL 和开发期草稿服务不是云端协议，后端不得据此猜测或复制实现。

## 后端设计前必须确认

1. M0 已以脱敏样本和容量测量冻结 `WorkDocument.schemaVersion=1` 的工程基线；真实前端往返样本仍必须在 M1 联调记录中验收。
2. M0 已冻结 API 响应、错误码、幂等、分页和请求 ID 规则；M1 必须以自动化测试实现并验证它们。
3. M1 开始前需由业务方确认测试与生产域名、Cookie/CORS、供应商及团队验证环境权限。
4. 未来若引入异步图纸生成、App 或在线支付，必须单独立项并创建新的接口版本；不改写 M1 契约。

## 变更规则

- 每次确定接口前，先更新本文件的接口版本、用途、请求示例、响应示例、错误码和兼容策略。
- 契约变更必须同步新增或更新 `tests/` 的接口验证，并在 `logs/` 记录联调结果。
- 不通过读取前端本地存储、构建文件或硬编码前端内部状态代替 API 契约。
- 接口字段或行为若有破坏性变化，必须先标注版本影响和前端迁移动作，再实现后端改动。

## M2 后续用户能力契约引用（2026-08-30）

用户确认纳入后续范围的“我的已发布内容、作者/资料页、收藏智能集合、图纸册库存可制作性、完成制作并扣减”，其字段与行为真相统一维护在 [M2 图纸册与灵感库 API 的后续用户能力章节](接口/M2-图纸册与灵感库-API.md)。本入口不复制字段定义。

当前冻结的关键边界：作者公开页必须包含头像、公开帖子统计（获赞数/收藏数）和公开帖子列表；所有匿名 `PublishedCommunityPost.author` 都包含可路由的 `creatorId`，它只可为 `community_creator_profiles.public_id`，绝不可使用内部用户/owner 数字 ID；收藏中的撤回/下架/删除内容保留不含治理原因的“内容不可用”占位，用户仍可幂等取消收藏；`makingStatus=completed` 与库存 `complete` 始终独立，前端不得以连续请求伪造原子操作。三个新增社区读取路由已由后端实现，尚待 FE 接入和 QA 验收，未完成前不构成本地或公开上线能力。
